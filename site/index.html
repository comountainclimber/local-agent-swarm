Core architecture

One control plane. Any number of inference nodes.

A coding agent's hands operate in a local git worktree while its model's brain may run on another Mac or GPU host. The scheduler knows endpoint URLs, capabilities, health and capacity — never whether traffic rides Wi‑Fi, Ethernet or Thunderbolt.

user → frontier planner → task DAG → scheduler → coding agents in worktrees
                                            ↘ HTTP inference nodes
                            verification → review → human-approved integration
Components

Each part owns one thing.

The orchestrator connects existing systems and records their outcomes. Magnitude owns model serving, git owns history, and runtimes like Codex CLI or OpenCode own the edit/tool loop.

Control loop

Plan once, execute many.

Tight scopes, explicit acceptance criteria and executable checks make smaller models far more effective than a single broad prompt.

  1. A user supplies a goal and constraints.
  2. The frontier planner inspects the repo and produces a task DAG plus work packets.
  3. The orchestrator validates packet shape, acyclicity, permissions and verification commands.
  4. The scheduler leases ready tasks and suitable inference capacity.
  5. Agent processes iterate inside isolated worktrees.
  6. Verification evidence and structured results are persisted.
  7. Independent reviewers accept, reject, or propose bounded repair work.
  8. Workers may propose follow-ups; scope expansion needs approval.
  9. Accepted branches integrate in dependency order; aggregate checks run.
  10. A frontier model does final review; a human controls merge and push.
Routing policy

Right model, right node.

Eligibility first — health, capacity, model, capabilities, context window — then explicit, observable ranking: least active sessions, configured preference, stable tie-break.
